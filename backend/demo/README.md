# Переносимый демонстрационный комплект

Заказчик подтвердил, что данные проекта демонстрационные и предназначены
для публикации вместе с исходниками. Этот комплект обеспечивает перенос
текущего состояния без отправки частной резервной копии PostgreSQL.

- `snapshot.json`: 20 пользователей, 19 проектов, 19 записей файлов,
  34 категории и 78 связей проектов с категориями; имена, описания,
  статусы и связи сохранены из демонстрационной БД.
- `files/`: пять файлов, которые раньше находились только в локальных uploads.
- Иллюстрации остальных работ уже включены в `frontend/assets`.
- Для каждого файла в снимке есть размер и SHA-256: seed проверяет целостность.
- Пароль **новых** демонстрационных аккаунтов: `password123`.
  Старые passwordHash, токены восстановления, `.env` и письма не экспортированы.

## Загрузка

Из корня репозитория: `npm run setup`, затем `npm start`.
Основная БД — PostgreSQL; альтернатива без установки сервера:
`npm run setup:sqlite`. Оба варианта импортируют один и тот же комплект.

Повторный seed не заменяет существующие проекты, файлы, профили и пароли.
Он проверяет оригиналы и добавляет недостающие сущности. Если существующий
файл с тем же storageKey отличается, импорт останавливается без перезаписи.

## Старые технические примеры

Полный перенос сохраняет не только 12 опубликованных работ, но и шесть
технических работ `PENDING` и одну `REJECTED` из прежних проверок.
Некоторые содержат пустые проекты или намеренно минимальные файлы: в частности,
`smoke.glb` — 12-байтовый тестовый заголовок, а не полноценная 3D-модель.
Это сохранённая история проверок, **не ошибка копирования репозитория**.
Эти работы не видны гостям в каталоге. Для демонстрации модерации можно
создать новый проект с полноценными файлами через интерфейс.

## Обновление комплекта в будущем

Только после проверки, что база по-прежнему содержит исключительно демо-данные:

```powershell
cd backend
node prisma/export-demo.mjs --confirm-demo-data
```

Экспорт читает рабочую БД, но не изменяет её. Затем обязательно просмотрите
diff JSON и файлы перед коммитом. Реальные пользовательские данные этим
способом публиковать нельзя. После изменения комплекта повторите развёртывание
на пустой тестовой БД, чтобы не принять работу старой установки за успех импорта.
